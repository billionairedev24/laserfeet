Install

Install in one line

The installer downloads lf for your computer, checks its SHA-256 checksum against the release, and refuses to install anything that doesn't match.

Prefer to check first? Every release on GitHub lists SHA256SUMS and signed build provenance. You can also build from source with Go 1.24+: go install ./cmd/lf.

  1. Mac or Linux curl -fsSL https://billionairedev24.github.io/laserfeet/install.sh | sh
  2. Windows (PowerShell) irm https://billionairedev24.github.io/laserfeet/install.ps1 | iex
  3. Add Laser Feet to VS Code for live errors, autocomplete and hover (download laserfeet.vsix from the latest release) code --install-extension laserfeet.vsix
  4. Start a project and run it lf new my-app cd my-app lf run app.lf lf test app.lf

  • 0.14Everyday tools

01Your first program

A program starts in its launch block. show prints a line. Notes start with -- and are ignored.

-- my first program launch { show "Hello, world" }

Save it as hello.lf and run lf run hello.lf. For quick scripts you can leave out launch; the lines then run from top to bottom.

02Values

Give a value a name with =. Inside a beam you don't write types; Laser Feet works them out from what you assign. Use lock for a value that must never change, and put any value inside text with { }.

launch { name = "Ada" age = 36 lock speedOfLight = 299792 age = age + 1 show "{name} is {age}" show "Light: {speedOfLight} km/s" colors = ["red", "green"] colors.add("blue") show colors[0] show count(colors) city = {name: "Austin", state: "TX"} show city.name }

03Types and numbers

Laser Feet is typed: beam inputs, what a beam gives, and object fields all say their type. Values inside a beam take the type of what you put in them. Before anything runs, lf run checks every type, so mistakes show up as clear messages instead of crashes. You can also run lf check app.lf on its own.

object Item { name: Text price: Decimal quantity: Int = 1 } beam total(items: List[Item]) gives Decimal { sum: Decimal = 0 each item in items { sum = sum + item.price * item.quantity } send sum } launch { cart = [Item("Lamp", 19.99, 3), Item("Bulb", 0.10)] show total(cart) -- exactly 60.07 show 0.1 + 0.2 -- exactly 0.3 show 7 / 2 -- 3.5 show fixed(12.5, 2) -- "12.50" }
TypeHolds
IntWhole numbers. Going past about 9.2 quintillion is an error, never a silent wrap-around
DecimalExact decimals, for money: 0.1 + 0.2 is exactly 0.3. A number written with a point, like 19.99, is a Decimal
FloatFast, approximate decimals, for measurements. Make one with float(x)
Text / FlagText / yes or no
List[Item] / Map[Int]A list of items / named entries holding Ints
Item?An Item, or nothing
GreeterAny object that follows the rule Greeter
Beam(Int) gives TextA beam, for passing beams around
JsonData from outside, like a request body, before it's checked

Numbers mix safely. An Int can be used wherever a Decimal or Float is needed, and dividing Ints gives an exact Decimal. A Float and a Decimal never mix by accident; convert on purpose with float(x) or decimal(x). int(x) drops anything after the point, round(x) rounds halves away from zero, and fixed(x, 2) shows exactly two places.

Nothing is never a surprise. Only a ? type can be nothing, and Laser Feet makes you check it before you use it:

object User { name: Text } beam find(users: List[User], wanted: Text) gives User? { send users then findFirst(name is wanted) } launch { users = [User("Ada"), User("Tobi")] found = find(users, "Kemi") when found is nothing { show "No Kemi here" stop } show found.name -- safe: found can't be nothing on this line }

Data from outside gets checked once. Item.from(json) turns JSON into a real Item, checking every field. In a web route, a mismatch automatically becomes a 400 reply that names the field, like {"error": "price must be Decimal, but got text"}.

Empty lists need a type. Laser Feet can't tell what [] will hold, so write it: names: List[Text] = []. Values set to nothing at first need one too: winner: User? = nothing.

04Beams

A beam is a function: inputs go in and send shoots the result out. Each input says its type, and gives says what comes out. A beam that sends nothing back leaves out gives. Inputs can be named when you call it.

beam add(a: Int, b: Int) gives Int { send a + b } beam factorial(n: Int) gives Int { when n <= 1 { send 1 } send n * factorial(n - 1) } launch { show add(2, 3) show add(b: 10, a: 1) show factorial(5) double = x => x * 2 show double(21) }

x => x * 2 is a one-line beam, handy for passing to other beams. It takes its types from where it's used, so it doesn't need them written.

Generics. A beam, object or choice can work with any type by naming it in brackets. Laser Feet works out what the name stands for at each use and checks everything against it.

beam firstOr[T](items: List[T], fallback: T) gives T { when count(items) is 0 { send fallback } send items[0] } object Page[T] { items: List[T] total: Int } launch { show firstOr([3, 4], 0) + 1 -- T is Int show firstOr(["a"], "z").upper() -- T is Text page = Page(["Lamp", "Bulb"], 2) -- a Page[Text] show page.items then join(", ") }

05Objects and rules

An object is a blueprint listing fields and the beams that work on them. Inside its beams, fields are used by name and me means the object itself. A rule lists beams an object promises to have; follows makes the promise and Laser Feet checks it.

rule Greeter { beam greet() gives Text } object User follows Greeter { name: Text age: Int visits: Int = 0 beam greet() gives Text { send "Hi, I am {name}" } beam visit() { visits = visits + 1 } } launch { ada = User(name: "Ada", age: 36) ada.visit() show ada.greet() show "Visits: {ada.visits}" tobi = User("Tobi", 12) show tobi }

Every field has a type. Make an object by calling its name, filling fields in order or by name. Fields with a default, like visits: Int = 0, can be left out. Put private before a field or beam to keep it inside the object: only the object's own beams can use it, and private fields are never sent as JSON or filled from it.

Choices and focus

A choice is a value that is exactly one of a few options, and options can carry data. focus runs the arm that matches, and Laser Feet checks that every option has an arm, so adding an option later points you at every place that needs to handle it.

choice Shipment { Waiting OnTheWay(carrier: Text, eta: Date) Delivered(on: Date) } beam track(s: Shipment) gives Text { focus s { Waiting { send "packing your order" } OnTheWay(carrier, eta) { send "with {carrier}, arriving {eta}" } Delivered(on) { send "delivered on {on.weekday}" } } } launch { show track(Shipment.Waiting) show track(Shipment.OnTheWay("DHL", date("2026-11-10"))) show track(Shipment.Delivered(date("2026-11-06"))) }

As JSON, an option without data is just its name ("Waiting") and one with data says which it is: {"kind": "Delivered", "on": "2026-11-06"}. focus also works on plain values: focus code { 200 { … } 404 { … } otherwise { … } }.

06Decisions and loops

when runs a block if the answer is yes; chain more checks with otherwise when. Compare with is, is not, < and >, and combine answers with and, or and not.

launch { score = 72 when score >= 90 { show "A" } otherwise when score >= 70 { show "B" } otherwise { show "Keep going" } each n in 1 to 10 { when n % 2 is 0 { skip } when n > 7 { stop } show n } loop 2 times { show "Zap" } }

skip jumps to the next item and stop leaves the loop. loop while repeats as long as its answer is yes.

07Chaining with then

then hands the result on its left to the beam on its right as the first input. Inside keepIf, turn and sortBy, use the item's fields by name, or it for the item itself.

When the left side is a calculation, add brackets to show what then takes: (price * quantity) then round passes the whole result, and "Team: " + (names then join(", ")) passes only names. Without them, Laser Feet asks you to choose, because either reading is possible.

object User { name: Text age: Int } launch { users = [User("Ada", 36), User("Tobi", 12), User("Kemi", 25)] adults = users then keepIf(age >= 18) then sortBy(name) show adults then turn(name) then join(", ") show [4, 8, 15, 16, 23, 42] then keepIf(it > 10) then sum }

08Handling problems

Wrap risky work in attempt. If anything fails, the fails block runs and receives the problem. Use fail to report one yourself.

beam divide(a: Int, b: Int) gives Decimal { when b is 0 { fail "can't divide {a} by zero" } send a / b } launch { attempt { show divide(10, 2) show divide(10, 0) } fails problem { show "Caught: {problem}" } show "Still running" }

Fail with a choice to say exactly what went wrong, and catch just that kind of problem with fails p: Type. An attempt can have several fails, tried in order; a problem none of them matches carries on outwards.

choice PayProblem { Declined(reason: Text) TooBig(limit: Decimal) } beam pay(amount: Decimal) gives Text { when amount > 100 { fail PayProblem.TooBig(100) } send "paid {amount}" } launch { attempt { show pay(500) } fails p: PayProblem { focus p { TooBig(limit) { show "the limit is {limit}" } Declined(reason) { show reason } } } fails problem { show "something else: {problem}" } }

09Doing things at the same time

Put fast in front of work to start it and carry on straight away. It gives you a job; wait job gives its result when it's ready. fast each runs its block for every item of a list at the same time, on as many workers as your computer has cores, and gives back what each one sent, in the original order.

beam brew(drink: Text) gives Text { pause(0.3) send "{drink} is ready" } beam square(n: Int) gives Int { pause(0.1) send n * n } launch { tea = fast brew("Tea") coffee = fast brew("Coffee") show wait tea -- both were brewing at the same time show wait coffee squares = fast each n in 1 to 6 { send square(n) } show squares }

Safe by design. Fast work can read values from outside it but never change them, and lf check refuses code that tries. Results travel back through send and wait instead, so two pieces of work can never trip over the same value, and you never need a lock.

Problems and time limits. If fast work fails, the problem appears at its wait, where attempt can catch it. wait job for 5 seconds gives up after a time limit. web.fetch(url) calls another web service and lets other fast work run while it waits for the reply.

Every core: fast each runs its items truly in parallel, one per core. While they run, nothing made before they started can change (even from inside a beam an item calls), so parallel work can't trip over itself; each item makes and changes its own values freely. A single fast job and web requests take turns, switching whenever one waits on a database, the network or pause.

10Web apps

use web brings in the web library. Add routes with server.get, server.post or server.on (any method), then start the server. To use the request in a route, name it: write as request before the route's {. Path parts written as :name then arrive in request.params. A route that doesn't need the request leaves the name out.

use web server = web.open(8080) server.get("/hello") { send "Hello from Laser Feet" } server.get("/square/:n") as request { n = int(request.params.n) send {number: n, square: n * n} } launch { show server.visit("/hello") show server.visit("/square/7") show server.visit("/missing").status fast server.start() }

What a route sends decides the reply. Text is always sent as plain text, so nothing a visitor types can turn into a web page. Lists, maps and objects become JSON. web.page(html) sends HTML on purpose, with visitor input cleaned by web.escape(x), and web.status(404, "Not found") sends an error code. server.visit tries a route without a browser, which is handy in tests.

In the playground, start lists your routes instead of opening a port. On your computer, lf run app.lf serves real pages at http://localhost:8080.

Accounts, sessions and pages

Everything a real web app needs is built in. server.sessions(secret) remembers each visitor in a signed cookie, use auth hashes passwords with Argon2id, server.before guards pages, and web.render fills in HTML templates, escaping every value so visitor input can never become HTML. Once sessions are on, other sites can't submit forms on a signed-in visitor's behalf.

use web use auth server = web.open(8080) server.sessions(env("SESSION_SECRET", "")) -- make one with: lf secret server.files("/static", "public") -- CSS, images, scripts server.limit("/login", 10, minutes(1)) -- slow down password guessing server.before() as request { when request.path.startsWith("/account") and not request.session.has("user") { send web.redirect("/login") } } server.post("/login") as request { email = request.form.email password = request.form.password when email is nothing or password is nothing { send web.status(400, "Enter your email and password") } user = findUser(email) -- your own beam when user is nothing or not auth.check(password, user.passwordHash) { send web.render("views/login.html", {error: "Wrong email or password"}, 401) } request.session.set("user", text(user.id)) send web.redirect("/account") }

A template is HTML with Laser Feet in braces: {name}, {each p in products} … {end}, {when user is nothing} … {otherwise} … {end} and {use "views/header.html"}. lf check reads your templates too. Replies can carry headers and cookies: web.reply(data).header("Cache-Control", "no-store").cookie("theme", "dark", days(30)). The complete example in examples/shipments has sign-up, sign-in, pages, a JSON API and PostgreSQL, with tests.

11Testing

A test block holds expect checks. lf test file.lf runs every test and reports which passed; lf test alone runs every file with tests in the folder, and lf test --cover also lists the lines your tests never reach. In the playground, press Run tests.

beam discount(total: Decimal) gives Decimal { when total >= 100 { send total * 0.9 } send total } test "big orders get 10 percent off" { expect discount(200) is 180 } test "small orders pay full price" { expect discount(50) is 50 }

12Sharing your program

lf build turns a program into one standalone file. The people you give it to don't need Laser Feet, Go, or anything else installed.

lf build app.lf -- makes ./app (app.exe on Windows) lf build app.lf -o shop -- picks the name ./app

The file carries a SHA-256 checksum of your program and refuses to start if it was changed or damaged after you built it. Files your program uses with use "file.lf" are packed in too. It runs on the same kind of computer you built it on, so build on a Mac for Macs and on Windows for Windows.

In Docker. Every project made with lf new has a Dockerfile. It runs your tests, builds the app with the official Laser Feet image, and ships an image that holds only your built program: no shell, no operating-system packages, running as an unprivileged user.

docker build -t my-app . docker run --rm -p 8080:8080 my-app

The official image, ghcr.io/billionairedev24/laserfeet, comes with signed build provenance for both Intel and ARM servers.

13Saving data

use store gives you a small built-in database. Records are maps with an id that Laser Feet gives them. Everything is saved to a file after each change, so it survives restarts.

use store launch { db = store.open("shop.json") -- in the playground this stays in memory db.add("products", {name: "Laser pointer", price: 12.5}) shoes = db.add("products", {name: "Running shoes", price: 89}) db.update("products", shoes.id, {price: 79}) show db.find("products", shoes.id) show db.count("products") cheap = db.all("products") then keepIf(price < 50) show cheap then turn(name) }
BeamWhat it does
store.open(file)Open (or create) a store saved in that file
store.memory()A store that isn't saved, handy for tests
db.add(name, record)Save a record and give back the saved copy with its id
db.all(name) / db.find(name, id)Every record / one record, or nothing
db.update(name, id, changes)Change some fields; gives back the record, or nothing
db.remove(name, id) / db.count(name)Delete a record (yes if it existed) / how many there are

Safe by default: the file is written to a temporary copy first and then swapped in, so a crash never leaves it half-written, and only you can read it. Changing a record you got back doesn't save it; use update.

15Splitting code into files

Put beams and objects in another .lf file and bring them in with use. The file's name becomes the name you reach them by.

-- prices.lf beam withTax(amount: Decimal) gives Decimal { send round(amount * 1.0825, 2) } -- app.lf use "prices.lf" launch { show prices.withTax(100) }

Paths are relative to your main program's folder, and Laser Feet refuses paths that point outside it. Only the main file runs its launch and test blocks. See the To-do API example for a complete app split across two files.

16Databases

use postgres connects to PostgreSQL with Laser Feet's own driver. Values go in a list and are sent separately from the SQL as $1, $2…, so nothing a visitor types can change your SQL. Results come back typed: numbers as Int or exact Decimal, true/false as Flag, json columns as Json.

use postgres db = postgres.open(env("DATABASE_URL")) db.run(""" create table if not exists products ( sku text primary key, name text not null, price numeric(12, 2) not null ) """) db.run("insert into products values ($1, $2, $3)", ["LAMP-1", "Desk lamp", 19.99]) cheap = db.query("select name, price from products where price < $1", [50]) lamp = db.first("select * from products where sku = $1", ["LAMP-1"]) -- a row, or nothing object Product { sku: Text name: Text price: Decimal } products = db.query(Product, "select * from products order by name") -- List[Product], every field checked one = db.first(Product, "select * from products where sku = $1", ["LAMP-1"]) -- Product? transaction with db as tx { tx.run("update products set price = price * 0.9 where price > $1", [100]) tx.run("insert into price_log (note) values ($1)", ["10% off"]) } -- both happen, or, if anything fails, neither does

How a transaction reads: transaction with db as tx starts a transaction on db and calls it tx inside the block. Everything done through tx is kept only if the whole block finishes; if anything fails, all of it is undone. tx has the same beams as db, and you can pick another name.

BeamWhat it does
postgres.open(url)Connect, like postgres://user:password@host:5432/shop; keeps a pool of up to 10 connections
db.query(sql, values)Every row, as a list of maps; db.query(Product, sql, values) gives a List[Product]
db.first(sql, values)The first row, or nothing; db.first(Product, …) gives a Product?
db.run(sql, values)Change data; gives how many rows changed
transaction with db as tx { }All or nothing; any problem undoes the whole block

Secure by default: a remote database is reached over TLS with its certificate checked (sslmode=verify-full); a database on the same machine doesn't need TLS. Login uses SCRAM-SHA-256, which also proves the server is real. sslmode=prefer is refused because it can quietly drop encryption. Put an object first, db.query(Product, …), and every row comes back as a checked Product; column names like created_at fill fields like createdAt. Dates, times and UUIDs arrive as Date, Time and UUID. A complete API is in examples/inventory.

17Packages

A package is Laser Feet code in a git repository, or a folder inside one, with a package.lf file. lf get adds it to your project; then use it by its address.

lf get github.com/billionairedev24/laserfeet/packages/textkit@main -- app.lf use "github.com/billionairedev24/laserfeet/packages/textkit" launch { show textkit.slug("Code at the Speed of Light") -- code-at-the-speed-of-light }

lf get writes two files to keep in git. sole.list says which packages and versions you use. sole.lock records the exact commit and a SHA-256 of each package's code. The packages themselves go in a .sole folder that git ignores; anyone who clones your project runs lf get to fetch them.

CommandWhat it does
lf get host/owner/repoAdd a package at its newest vX.Y.Z tag
lf get host/owner/repo@v1.2.0Add or change to a version: a tag, a branch, or a commit
lf getInstall everything in sole.list, exactly as locked
lf remove host/owner/repoStop using a package

Safe by default: installing never runs any code, and only .lf files are installed. The lock pins exact commits, so a moved tag or a branch with new commits can't change what you get. Before every run, test and build, each package is checked against its SHA-256, and changed code is refused. A package can only use its own files and other packages, never your project's files.

Making a package is just a repository with a package.lf; its beams and objects are what users reach through its name. Tag releases as v1.0.0, v1.1.0, and so on. A package that needs other packages lists them in its own sole.list (need github.com/someone/words v1.2.0); lf get installs them too. Each package is installed once: when two ask for different versions, the newer one is used, so keep newer versions working for code written for older ones.
